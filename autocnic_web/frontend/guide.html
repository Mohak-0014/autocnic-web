Guide

Preparing a repo for AutoCNIC

AutoCNIC analyzes projects organised as named computation steps. Your repo needs one extra file, autocnic_pipeline.py, that tells the app what the inputs and steps are. Your own code stays as it is.

Download the starter template Back to Analyze

1. Repo layout

your-repo/ ├── autocnic_pipeline.py # required: PIPELINE, SAMPLERS, INITIAL_INPUTS └── my_project/ # your code, any package name ├── __init__.py └── logic.py # plain functions, one per step

The file can also live in a subfolder. If the repo holds exactly one autocnic_pipeline.py (up to 3 folders deep), the app finds it. If it holds several, paste the GitHub link to the folder you want.

2. Write your step functions

Each step is a plain function. Name its parameters after the inputs or steps it reads; that is how the app wires the graph.

# my_project/logic.py def ticket_price(base_fare, seats): return round(base_fare * seats, 2) def booking_fee(member, card_fee_rate, ticket_price): if member: # members pay nothing, so the fee only return 0.0 # depends on card_fee_rate for non-members return round(ticket_price * card_fee_rate, 2) def total_due(ticket_price, booking_fee): return round(ticket_price + booking_fee, 2)

You don't declare which dependencies are conditional. The app finds out by running experiments, for example that booking_fee only depends on card_fee_rate when member is false.

3. Add autocnic_pipeline.py

import random from autocnic.pipeline import Pipeline # provided by the app from my_project.logic import ticket_price, booking_fee, total_due PIPELINE = Pipeline("ticket_checkout") PIPELINE.input("base_fare") PIPELINE.input("seats") PIPELINE.input("member") PIPELINE.input("card_fee_rate") PIPELINE.step("ticket_price")(ticket_price) PIPELINE.step("booking_fee")(booking_fee) PIPELINE.step("total_due")(total_due) _rng = random.Random(0) SAMPLERS = { # one random-value function per input "base_fare": lambda: round(_rng.uniform(10, 200), 2), "seats": lambda: _rng.randint(1, 6), "member": lambda: _rng.choice([True, False]), "card_fee_rate": lambda: round(_rng.uniform(0.0, 0.05), 3), } INITIAL_INPUTS = { # optional starting values "base_fare": 80.0, "seats": 2, "member": False, "card_fee_rate": 0.02, }
NameRequiredWhat it is
PIPELINEYesA Pipeline with at least one .input() and one .step().
SAMPLERSYesA dict with a function for every input that returns a realistic random value. Cover the whole range, including values that switch branches.
INITIAL_INPUTSNoStarting values. Any input left out gets one sampler draw.

4. Other ways to declare reads

  • By parameter name (default): PIPELINE.step("subtotal")(compute_subtotal).
  • Explicitly, to pin the exact dependency list: PIPELINE.step("subtotal", reads=["unit_price", "quantity"])(fn). The names must still match the function's parameters.
  • Module globals: PIPELINE.step("fee", infer_reads=True)(fn) uses static analysis to find inputs the function reads as bare global names.

5. Rules that avoid most errors

  • Only the Python standard library and modules inside your repo are available. No third-party packages (numpy, pandas, …), and don't add autocnic to your requirements.
  • Keep step functions pure: no network, file access, clocks or randomness inside them.
  • Steps must accept any value the samplers can produce. A crash during discovery stops the analysis.
  • Put all imports at the top of autocnic_pipeline.py.
  • Each package folder needs an __init__.py.
  • No cycles: a step can't read itself or anything that reads it.
